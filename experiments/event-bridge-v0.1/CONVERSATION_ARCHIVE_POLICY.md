# XSA｜真实会话与协作演进公开规范

> 状态：Draft，计划迁移至独立仓 `xingtu-super-agent`；当前不会自动发布至主分支。

## 初衷：以终为始，真实记录

XSA 不只展示最终代码，更公开“用户提出目标 → Agent 分工 → 方案争论 → 纠偏 → 提交 → 审查 → 实测 → 再迭代”的完整工程过程。目的不是写漂亮的成功故事，而是使后来者理解为什么这样设计、哪些试验失败、哪些判断改变。

用户已明确允许将其与助手的项目协作聊天公开，**包括原始聊天记录**。因此默认采取“原始证据 + 忠实整理 + 决策索引”三层存档，而非仅发表润色版。

## 三层材料

1. `transcripts/`：逐轮原文。必须来自可核对的会话导出或用户明确提供的文本，保留角色、时间（若可核）、顺序和来源；任何删除以 `[已脱敏：类别]` 标注。不能用总结材料冒充逐字原文。
2. `narratives/`：可阅读的忠实整理，保留核心原话、不同意见、纠偏节点、未解决问题；编辑调整注明“整理稿”，不伪造引语。
3. `decisions/`：ADR、关键决策、取舍理由、后续变化与对应代码/PR/测试链接，以稳定 ID 相互引用。

## 原文公开的必要边界

- 不上传密钥、Access Token、Cookie、私有账号凭据、支付信息、私人地址、联系电话、个人设备绝对路径和可关联真实身份的记录。
- 私有业务源码、企业客户/同事信息及未经授权的第三方私人会话不能因为包含在聊天中就直接公开。
- 截图与聊天附件单独审查；使用文字占位符记录缺失附件，不擅自搬运。
- 如果脱敏影响技术结论，提供脱敏原因与可公开的替代证据；不编造断掉的上下文。
- 公开审核重点是确保证据真实、引用准确、风险可控，而不是抹除失败或人为美化历史。

## 迁移计划

在新建 `xingtu-super-agent` 仓库前，本文件及其他实验草案先留在 `xingtu-harness` Draft PR。待独立仓创建后按原始会话导出、GitHub PR、提交 SHA、运行回执建立时间线；以当前可见会话整理的材料必须标注“基于当前会话上下文的整理”，不冒充跨会话完整原文。用户提供完整会话导出后，再补充逐字稿及 diff。

## 引用规约

引用 DeepSeek Super Agent 时以官方仓库和文档为第一手资料，说明其研究原型性质；“LLM + Harness + XSA 协同扩展”是行途提出的组合式工程表达，不是 DeepSeek 官方公式。所有 XSA 功能必须标 `design` / `mock` / `verified` / `production`，不得混淆。
