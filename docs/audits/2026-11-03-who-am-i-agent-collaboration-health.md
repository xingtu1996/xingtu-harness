## 1. 证据分级规则与审计范围

- **有证据**：本次通过可访问 GitHub API 回读的仓库/Issue/PR 状态、内容与合并记录，或本轮可逐字看到的首答。即便有 PR，仍不能直接推出测试通过或真实使用。
- **用户陈述**：在当前/既往聊天中由用户明确表达的身份定位、意图、偏好、口径和操作要求；可确认为“用户说过”，不是外部客观事实的证明。
- **推测**：依据多次行为或选择归纳的性格、能力、价值判断，须注明推测与限制。
- **未知**：没有权限、记录不完整、未能独立回读或没有执行测试的事项；不得以合理性代替证据。

检索样本：本轮可见首答与用户要求、历史上下文检索摘要、若干公开 GitHub Issue/PR 的 API 回读；另以已授权私有资料辅助交叉核对，但**不向公开仓转录私有材料**。这不是全部历史会话、全部仓库或全部执行日志的穷尽审计，存在选择偏差。

## 5. 意图理解审计

长期目标不是“拥有更多仓库/Prompt/Agent”本身，而是：让一个目标进入系统后，合法且低摩擦地经历 **理解背景 → 认领任务 → 受控执行 → 证据校验 → 可追溯回执 → 下次冷启动接力**；在内容侧沉淀可复用作品和商业检验。此目标由用户持续陈述，并见 [Issue #5 的目标定义](https://github.com/xingtu1996/xingtu-harness/issues/5#issuecomment-6600779049)。

不满意行为：重复追问、丢前置条件、把“规划”称“完成”、只生成提示词不落实际产物、无凭证宣布运行成功、在隐私/审批边界含糊、消耗额度换重复讨论。这些是用户表达过的协作要求；**未对发生频率作客观统计**。

最短改善路线：先读当前 Issue、最新 PR 和上次回执，再做任何规划；输出中每项标 `user_statement / verified / inferred / unknown`；遇到证据缺口主动降级声称；低风险做完带链接回执，高风险只产生待审批项。

## 7. 主要瓶颈：结论、证据、风险

| 方面 | 症状 | 风险 |
|---|---|---|
| 记忆/上下文 | 偏好分散在聊天摘要与不同 Agent 私有记录，旧决策没 superseded 关系 | 重问、复用过时事实 |
| 任务接力 | Issue、PR、草稿、Session、定时产物分散，缺唯一 task_id/next_action | 多 Agent 重复劳动、任务被淹没 |
| 交付质量 | “已提交”“已合并”“已实跑”“业务验收”被混淆 | 误放行、重复发布 |
| 工具和权限 | 连接器与本机读写/公众号能力不等同 | 虚构能力或反复审批 |
| 成本 | 模型倍率、额度截图不能代表任务总成本，缺跨工具统一收据 | 低单价多返工反而高成本 |
| 隐私 | 多条线有本地会话/客户/截图风险，组合识别也可能泄露 | 私密内容进入公开 git 历史不可轻易撤销 |
| 回执 | 缺实际运行输出、文件哈希、失败原因、阻断状态、人工批准记录 | 冷启动不能确定上一轮做到哪 |

## 8. 三个最小修复与可验证指标

### P0：一个任务唯一事实源，解决跨会话失忆与重复提问

- **动作**：每项跨 Agent 任务用一个 Issue 作为事实源，记录 `task_id / goal / owner / branch / status / evidence / next_action / updated_at`；PR 只承载变更，带 Issue 反向链接；旧决策增加 `superseded_by`，不覆写历史。
- **指标**：接下来 10 个跨 Agent 任务中，≥9 个首次接手无需用户重新解释目标；10/10 有唯一 Issue 与最新 next_action；抽样 3 次冷启动全部能准确复述“做到哪里/还差什么”。
- **解除障碍**：同题双跑、已交代背景反复补充、旧 PR 淹没新任务。

### P0：统一四级证据与回执门禁，解决虚假完成感

- **动作**：所有成果统一标 `run_success / artifact_observed / artifact_stale / unverified`；`run_success` 必须有执行命令或调用凭证、退出/回读结果、产物与校验哈希、测试范围、风险和下一步；失败不能改写成成功。
- **指标**：连续 10 个 PR/执行回执，状态有证据支撑比例 100%；不允许 `NOT_RUN` 写成 `PASS`；人工抽检 5 个声明，0 个与源证据冲突。
- **解除障碍**：文档即部署、代码提交即测试、草稿即发布、PR 合并即生产验收。

### P1：把权限、隐私和成本做成执行前门禁，解决返工与无效消耗

- **动作**：每个任务执行前记录 `data_class(L0–L3) / allowed_write_scope / approval_required / estimated_cost`；公开提交须先脱敏；涉及生产、身份、外部群发等不可逆操作人工审批；回执填 `actual_cost`，无法获得写 `unknown`。
- **指标**：连续 10 个公开 PR 隐私复核覆盖 100%、已发现敏感泄露 0；执行前和执行后权限状态一致；可比任务记录成本覆盖率 ≥80%，同类重复询问与无用调用次数建立基线并跟踪下降。
- **解除障碍**：公开泄露、权限错误、重复审批、便宜模型反复返工。

所有阈值是**拟议验收标准**，并非当前达成率；未来应按每轮实际记录复评。

## 9. 评分依据（评的是协作状态，不评用户能力）

用 0–4 的**审计等级**替代首答虚构精确分数：0=无可见证据，1=只有声明，2=有文件或局部操作，3=有可核实闭环，4=经多次独立复现与验收。只针对本次抽样：

| 维度 | 等级 | 依据 |
|---|---:|---|
| 长期目标识别 | 3/4 | 用户反复明确目标，Issue #5 能交叉印证；不代表目标已实现 |
| 历史事实与状态核对 | 2/4 | 读到公开 PR 和当前状态，但并非全部历史/本机记录 |
| 跨 Agent 冷启动接力 | 1/4 | 设计与交接资产有记录，真实冷启动验收未完成 |
| 交付证据与测试纪律 | 2/4 | 多个 PR 标注 NOT_RUN/Draft；亦有更正与合并记录，执行链不完整 |
| 产出闭环与业务收益 | 1/4 | 有内容/工程资产，缺统一的已发布、已使用和收益对照核验 |
| 隐私与权限边界 | 2/4 | 已有明确约束，公开仓是否全量通过隐私审计未知 |

**禁止解释为用户能力分或普适科学测量。** 与原回答的百分数不能做统计对比；本次等级仅帮助定位需要补什么证据。

## 10. 未知、限制与反向审查

- 原始首答已单独冻结，公开 PR 不包含其全文；公开 GitHub 中只有不可逆推的 SHA-256 指纹与问题分析。
- 对“做过哪些任务”只以具体提交/PR 判断产物和状态；不将其归因到某一个模型的单独能力。
- 当前无法证明全部背景、全量项目列表、模型额度使用、私有 Session、团队经营效果、自动化真实运行、公众号后台行为与跨 Agent 的实际总成本。
- 若公开 Issue/PR 与私有会话摘要冲突，以事件时间、当前 API 回读和真实执行回执优先；无法解释则写未知。
- 报告提交后仍须由人工核对公开安全和结论；仅提交 Draft PR，不自动合并、不关闭关联 Issue。
